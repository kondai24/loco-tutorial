## 記録の運用

- 新しい判断は、背景、決定、理由、代替案、影響を含む連番のADRとして記録し、この一覧から参照する。
- 未確定の案を採用済みとして記録しない。既存判断の具体化は該当ADRに追記し、別の判断への変更は新しいADRで旧ADRを置き換え、相互参照する。
- コードに影響する仕様判断が決まった場合は、該当ADRの記録も更新する。
- 「採用」は設計判断の合意を示す。実装済み・テスト済みを意味しない。

ADR 0004で詳細契約を具体化し、ADR 0005で公式構成・標準エラーへ統一した。`backend/`と`frontend/`へ実装した。実行・検証方法はリポジトリのREADMEを参照する。
