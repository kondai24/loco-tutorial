# ADR 0003: 確定した設計・仕様判断のADRへの集約

- 日付: 2026-10-31
- 状態: 採用

## 背景

移行に関する設計や仕様の判断を、会話に分散させずリポジトリ内で継続的に参照できるようにする。ユーザーから、仕様に関して決まった内容と意思決定をADRへ集約する指示があった。

## 決定

- `docs/adr/`を、確定した設計・仕様上の判断の正本とする。
- 採用した構成、機能範囲、制約、外部契約、受入条件と、それぞれの理由を対応するADRに記録する。
- 未確定の論点は採用済みの決定と区別する。
- 一覧は[README](README.md)で管理し、関連するADRを相互参照する。
- 判断を変更する場合は、変更理由と置き換え先を追跡できるようにする。
- 設計判断の採用と、実装・検証の完了を区別する。

## 採用理由

コードと同じリポジトリで判断を追跡でき、後から仕様や制約を確認するときに参照先が一意になる。

## 非採用案

- 会話だけを記録として残す案: 実装者や後の変更で根拠を参照しにくい。
- 複数の文書をそれぞれ判断の正本として扱う案: 更新が分散し、矛盾を生みやすい。

## 影響

今後仕様を具体化する際は、確定した内容を対応するADRへ記録する。未確定のAPI詳細を、今回のADR作成だけで確定・実装済みと扱わない。
