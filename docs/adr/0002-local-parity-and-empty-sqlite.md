# ADR 0002: 現行機能の維持と空のSQLiteからのローカル移行

- 日付: 2026-10-31
- 状態: 採用

## 背景

RailsからLocoへの移行では、既存データの移行を行わず、ローカルで現行と同じ機能を利用できる状態を目指す。移行先のDBとしてSQLiteを継続することが合意済み。

## 決定

### 維持する利用者向けの機能

- 質問の一覧、詳細、作成、編集、削除。
- 質問に対する回答の投稿、表示、削除。
- 質問のタイトル、名前、本文を必須とし、本文は5文字以上とする入力検証。
- 入力エラーの画面表示と、質問フォームの再入力・修正。
- 質問の削除に伴う関連回答の削除。
- 現在に近いUI、文言、操作、画面URL。

現行コードには回答の名前・本文に質問と同じ必須・長さ検証はない。移行を理由に新しい入力制約やログイン機能を追加しない。

### データと到達点

- SQLiteを使用し、質問・回答が空のDBから開始する。
- 旧DBのレコード、ID、既存セッションを引き継ぐ移行処理は対象外とする。
- 成功条件は、Railsを起動せず、ローカルで一覧・詳細・投稿・編集・削除・入力エラー表示を利用できること。
- 公開環境へのデプロイや切り替え、既存データ移行、新機能追加は今回の対象外とする。

## 採用理由

DBサーバーの準備や既存データの変換を必要とせず、画面とバックエンドの機能移植に集中できる。デプロイ環境の変更を同時に扱わず、ローカルでの同等動作を到達点として明確にできる。

## 非採用案

- PostgreSQLへの同時移行: 今回の到達点に必要がなく、環境構築と変更範囲が増える。
- 既存データの移行: ユーザーが空のDBからの開始を選択した。
- 公開環境までの移行: ユーザーがローカルでの同等動作を到達点とした。

## 根拠と限界

調査したソースは`app/controllers/questions_controller.rb`、`app/controllers/answers_controller.rb`、`app/models/question.rb`、`app/models/answer.rb`、`app/views/questions/`、`config/routes.rb`、`db/schema.rb`。現行Railsのテストファイルは雛形のため、機能の互換性がテストで保証されているとは扱わない。今回は静的調査のみで、現行・移行後の実行確認は行っていない。

`resources :answers`で定義された経路すべてに対応するコントローラ処理があるわけではない。現行画面・実装に存在しない回答編集などを、ルート定義だけから新機能として追加しない。

## 仕様化待ちの内容

API契約、空文字・空白・Unicodeの検証境界、DBの項目型とNULLの扱い、日時、存在しないIDの応答、削除の原子性、通信・保存失敗時の表示、画面とAPIの検証方法を具体化する必要がある。確認できていない実行時挙動を互換性の根拠として扱わない。
